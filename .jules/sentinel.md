## 2026-05-29 - Insecure Randomness in OTP and ID Generation
**Vulnerability:** The backend previously used `Math.random()` to generate security-sensitive tokens, passwords, and OTP codes. Standard pseudo-random number generators (PRNGs) like `Math.random()` are cryptographically insecure, meaning their outputs can be predicted if an attacker observes a sufficient number of previous values, potentially leading to unauthorized account access, OTP bypass, or administrative credential compromises.
**Learning:** Legacy development prioritized simplicity and standard library APIs over strict cryptographic security guarantees. Because the application was developed as a fast prototype, standard `Math.random()` functions were utilized without realizing the severe security implications when applied to OTP generation, session identification, and password creation.
**Prevention:** Always use cryptographically secure random number generators (CSPRNGs), such as the Web Crypto API's `crypto.getRandomValues()`, for any sensitive values (including tokens, IDs, passwords, and verification codes). Encapsulate these CSPRNG functions in clear utility functions like `secureRandomInt` and `secureRandomSuffix` to ensure they are consistently applied throughout the codebase.
