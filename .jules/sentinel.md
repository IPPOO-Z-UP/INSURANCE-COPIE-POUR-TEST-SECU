## 2026-05-30 - Replacement of Insecure Predictable Randomness (Math.random) with Cryptographically Secure Utilities
**Vulnerability:** The backend previously used `Math.random()` in several security-sensitive scenarios, including OTP code generation, agent matricule generation, temporary user passwords, and internal alphanumeric transaction/audit identifiers. `Math.random()` in JS/TS is a pseudo-random number generator (PRNG) that is deterministic and predictable. This allows an attacker to predict generated OTPs or credentials, leading to account takeover and duplicate transaction IDs.
**Learning:** Developers frequently default to `Math.random()` for convenience, without considering the security implications in backend processes (like OTPs, identifiers, or temporary passwords).
**Prevention:** Avoid `Math.random()` entirely in security-sensitive contexts. Always use the standard Web Crypto API (`crypto.getRandomValues`) to generate securely random numbers and string suffixes.
